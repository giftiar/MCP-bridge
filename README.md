## 🤔 这是什么

一个本地 MCP 服务器，把 Android 的无障碍能力、虚拟屏与输入注入封装成
AI 可以直接调用的工具。

**两种工作模式，互不干扰：**

*   **普通模式** — 用无障碍服务操作当前屏幕，不需要 root，不需要 Shizuku
*   **虚拟屏模式** — 在独立虚拟屏上运行应用，完全不占用你的屏幕

---

## 🏆 与普通自动化工具的区别

*   **🚀 真正的后台运行** — 虚拟屏模式下，AI 在完全隔离的屏幕上操作，
    你的手机主屏可以**同时正常使用**，互不干扰
*   **👁️ 实时可见** — 悬浮小窗实时显示虚拟屏画面，可拖动、双指缩放、折叠成圆球
*   **🧠 模式隔离** — 两种模式使用完全不同的工具集与提示词，
    AI 不需要知道存在另一种模式
*   **🛡️ 安全护栏** — 危险词拦截、节点失效计数、屏幕变化检测、急停悬浮球
*   **🔌 离线识别** — OCR 完全在本机运行，截图不会上传
*   **🎨 Material 3 界面** — 六套淡色主题，Android 12+ 支持莫奈取色

## 💻 环境要求

| 项 | 要求 |
|---|---|
| Android 版本 | 11 及以上（无障碍截图需要 API 30） |
| 悬浮窗权限 | **两种模式都需要**，用于急停悬浮球 |
| 存储权限 | 下载文件需「所有文件访问权限」 |
| Shizuku | 仅虚拟屏模式需要 |

### 虚拟屏模式的 Shizuku 要求

支持三种部署方式，行为不同：

| 方式 | 进程 SELinux 域 | 建屏 | 输入注入 |
|---|---|---|---|
| 官方 Shizuku（ADB 启动） | `u:r:shell:s0` | ✅ | ✅ 原生注入 |
| 官方 Shizuku（root 启动） | `u:r:shell:s0` | ✅ | ✅ 原生注入 |
| SUI / KernelSU 模块 | `u:r:magisk:s0` | ✅ | ⚠️ 降级到 `input` 命令 |

降级后点击约 71ms 一次，功能完整但略慢。建屏返回值为证：

```
OK id=56 1080x1920@440 inject=on(2)    ← 原生注入可用
OK id=56 1080x1920@440 inject=off(2)   ← 已降级
```

```
本机    http://127.0.0.1:18800/mcp
局域网  http://<手机IP>:18801/mcp  （需在设置中开启）
```

**令牌留空表示不验证。** 开启局域网时强烈建议设置令牌。

```json
  "paused": "no",
  "estop": "floating_ball (running)"
```

## 🖥️ 普通模式

用无障碍服务操作当前屏幕。**AI 操作和你的手会互相干扰**，适合：

*   你不在手机上做别的事
*   需要精确读取界面结构
*   需要文字输入和按键

### 能力

| 能力 | 说明 |
|---|---|
| 读取节点树 | 精确到像素的元素边界、文字、可点击性 |
| 按 ref 点击 | `@7` 引用，屏幕变化后失效 |
| 按坐标点击 | 用节点边界算出的中心，精度最高 |
| 文字输入 | `set_text` 直接写入 |
| 按键 | 返回、主页、最近任务、通知栏等 |
| OCR | 节点树读不到时用截图识别 |

### 界面元素

*   **状态卡片** — 左上角，实时显示 AI 在做什么
*   **急停悬浮球** — 右上角 52dp，点一下暂停、再点恢复、可拖动

### 🛡️ 安全机制

| 机制 | 行为 |
|---|---|
| 危险词护栏 | 命中「卸载」「支付」「删除」等拒绝执行 |
| 节点失效计数 | 同一元素连续 5 次无效则标记不可用 |
| 屏幕变化检测 | 快照后屏幕变了，旧 ref 操作被拒绝 |
| 急停 | 所有写操作立即被拦截 |
| 系统栏护栏 | 状态栏与导航栏禁止滑动拖拽（会崩溃 `SystemUI`） |

## 📺 虚拟屏模式

在独立虚拟屏上运行应用，**你的屏幕完全不受影响**。

### 工作原理

```
你的手机（主屏）
  │
  └─ MCP交互器 App（悬浮小窗、控制面板）
        │ Shizuku 绑定
        ▼
     Shizuku 用户服务进程（shell 身份）
        │ createVirtualDisplay
        ▼
     虚拟屏 1080×1920（私有，物理屏上看不到）
        └─ 运行任意 App
```

### 🪟 悬浮小窗

| 状态 | 外观 | 操作 |
|---|---|---|
| 折叠 | 38dp 圆球，绿色 | 点一下展开；拖动移动位置 |
| 展开 | 视频比例窗口，实时画面 | 单指拖动；双指缩放；点右上角 ▾ 折叠 |

位置自动保存，下次启动回到原位。

### 能力

| 能力 | 说明 |
|---|---|
| 建屏 | 自适应分辨率，默认取主屏短边，比例 9:16 |
| 截图 | `ImageReader` 全分辨率，不 fork 进程 |
| OCR | 离线中文识别，返回精确中心坐标 |
| 手势 | 点击、长按、滑动、长按拖拽 |
| 启动 App | `am start --display` |
| 旋转 | 跟随前台应用自动切换，也可 `vd_rotate` |
| 文字输入 | 自带输入法，直接 `commitText`，支持中文 |

### 🧹 清理机制

虚拟屏和用户服务进程有三层保护：

```
1. 冷启动扫描   —— 绑定成功后先清理再建屏
2. Binder 死亡   —— 客户端进程退出时立即清理
3. 轮询兜底      —— 每 3 秒检查客户端是否存活
```

清理范围严格限定为 `com.mcpmate.bridge:vd`，**不触碰任何第三方虚拟屏**。

设置页「虚拟屏管理」可手动查看和清理：

```
本应用虚拟屏: 1
id=56  mcp-vd-1761...  state=ON  rootTasks=1

本应用服务进程: 1
shell  12345  ...  com.mcpmate.bridge:vd

其他应用虚拟屏（不可操作）: 0
```

## ⚠️ 已知问题

### 输入法与主屏冲突

**现象：** AI 在虚拟屏输入时，主屏正在使用的输入法会被临时切走，你的输入会中断。

**原因：** Android 的输入法架构是全局单例，没有「每个屏幕一个输入法」。
`commitText` 是目前唯一能输入中文的路径，而它必须让本应用的输入法成为默认输入法。

**当前缓解：** 每次 `type_text` 结束后立即切换回你原来的输入法，冲突窗口约 120ms。

**仍未解决：**

*   如果在 AI 输入的同时你在主屏打字，两边都会失败
*   首次 `type_text` 可能失败（`ime_event` 显示 `type=0`），需重试一次

**建议：** AI 正在输入时暂时不要在主屏打字。

**为什么不能根治：** KeyEvent 注入需要窗口焦点，虚拟屏没有焦点；
`ACTION_SET_TEXT` 需要无障碍节点树，虚拟屏不在树里；
剪贴板命令在部分系统上不可用。没有第四条路。

### 虚拟屏无按键

虚拟屏没有窗口焦点，因此：

*   `KEYCODE_BACK` / `HOME` 无效
*   系统输入法无法绑定

**绕过方式：** 用 `open_app` 切换应用代替返回键。

### 虚拟屏不检查危险词

普通模式会拦截「卸载」「支付」等高危操作，**虚拟屏模式没有此保护**。

原因：虚拟屏只有 OCR 文本，无法像节点树那样精确判断点击目标。

**建议：** 在虚拟屏上跑敏感应用时格外注意。

### 重型应用可能导致服务被回收

**现象：** 在虚拟屏内运行内存占用很高的应用时，服务进程可能被系统回收，虚拟屏消失。

**原因：** 大型应用的内存占用，叠加虚拟屏缓冲与悬浮窗预览的帧缓存，
可能触发系统低内存回收。本应用的服务是 `dataSync` 类型，优先级不高。

**当前表现：** 服务会通过 `START_STICKY` 重启并重新建屏，但虚拟屏里的应用会关闭。

**缓解：** 把悬浮小窗折叠（折叠后不再拉预览帧）。

### 其他

*   部分应用会检测无障碍服务并拒绝返回节点树，这类应用需开启兼容模式
*   状态栏与导航栏禁止滑动拖拽（会崩溃 `SystemUI`），点击不受影响
*   MIUI 会把 400ms 以下的滑动判为 `fling`，默认滑动时长已改为 800ms

## ❓ 常见问题

### 服务开了但 AI 连不上

```
1. 确认主界面显示「服务 运行中」和监听端口
2. 确认地址是 http://127.0.0.1:18800/mcp
3. 如果设了令牌，客户端要带 Authorization: Bearer <令牌>
4. 检查是否开启了 VPN（可能拦截 127.0.0.1）
```

### 虚拟屏显示「未连接」

```
1. 检查 Shizuku 是否在运行
2. 检查 Shizuku 是否已授权本应用
3. 设置页 → 授权 Shizuku
4. 反复失败时：设置页 → 虚拟屏管理 → 清理本应用虚拟屏
```


### AI 看不到界面

```
普通模式：
  1. 确认无障碍服务已开启
  2. 如果是微信等应用，确认兼容模式已开启
  3. 尝试 ocr 代替 screen_snapshot

虚拟屏模式：
  1. 只有 ocr 一种方式，没有节点树
  2. 确认虚拟屏里有应用在运行
```

### 手动清理残留

```bash
# 查看
ps -A | grep mcpmate
dumpsys display | grep -o 'mDisplayId=[0-9]*' | sort -u

# 清理（需 root）
for pid in $(ps -A -o PID,ARGS | grep 'mcpmate.bridge:vd' | grep -v grep | awk '{print $1}'); do kill -9 $pid; done
```
